Desenvolvimento de uma Calculadora simples com Flutter

Notas de aula do professor Kleber de Oliveira Andrade — do estado ao resultado

Uma calculadora parece apenas um conjunto de botões. Mas o que deve acontecer quando alguém aperta dois operadores seguidos? E quando divide por zero, apaga um número negativo ou continua uma conta depois do resultado? Essas perguntas ajudam a aprender algo que será útil em qualquer aplicativo: transformar regras de comportamento em um domínio testável e só então conectá-lo à interface.

Nesta revisão de novembro de 2026, vamos trabalhar com o projeto completo e atual, sem combinar os exemplos antigos de 2020 com APIs novas. Ao final, você terá uma calculadora sequencial com decimais, troca de sinal, módulo, teclado físico e mensagens de erro que permitem recomeçar. O código mantém a autoria e a licença MIT do projeto original.

1. Conheça o resultado antes de escrever código

Comece experimentando três situações: 8 ÷ 2 deve resultar em 4; 8 mod 3 deve resultar em 2; e 8 ÷ 0 deve mostrar um erro sem impedir a próxima conta. Os chips de exemplo executam apenas comandos locais e não usam dados pessoais, conta de usuário ou serviços externos.

Regra central: a avaliação é da esquerda para a direita. A sequência 2 + 3 × 4 resulta em 20: primeiro confirmamos 2 + 3 e depois multiplicamos 5 por 4. Não há precedência de operadores nem parênteses. O símbolo % significa módulo euclidiano, não porcentagem: 8 % 3 = 2 e -8 % 3 = 1.

2. Prepare um ambiente reproduzível

A versão usada nesta aula é Flutter 3.50.0 com Dart 3.14.0. O Dart vem junto com o Flutter; não instale outra versão separadamente para este projeto. A versão está registrada em .flutter-version e no CI. Para reproduzir os testes Web, tenha também o Google Chrome instalado.

git clone https://github.com/kleberandrade/calculadora-flutter.git
cd calculadora-flutter
flutter --version
flutter pub get --enforce-lockfile
flutter run -d chrome

Execute uma linha por vez, dentro da pasta do projeto. O parâmetro enforce-lockfile verifica o conjunto de dependências já validado; não copie instruções antigas de Gradle 5.6. A configuração Android atual segue o template do Flutter 3.50: Android Gradle Plugin 9.3.1, Gradle 9.5.0 e Kotlin 2.4.20, com suporte Kotlin integrado. O Android mínimo é API 24 e o alvo iOS é 15+. Preparar SDKs, licenças e assinatura nativa é uma etapa separada da execução no Chrome.

4. Separe o domínio da interface

Há três arquivos principais: main.dart inicia o aplicativo e define o tema; calculator.dart apresenta a tela e traduz interações em comandos; memory.dart mantém entrada, operação pendente, resultado e erro. Memory não importa Flutter. Essa separação permite testar uma conta sem abrir a tela.

No domínio, uma operação é uma escolha explícita, em vez de uma string arbitrária. Este trecho é extraído do arquivo atual:

enum Operation {
  add('+'),
  subtract('-'),
  multiply('x'),
  divide('/'),
  modulo('%');
  const Operation(this.symbol);
  final String symbol;
  double calculate(double left, double right) => switch (this) {
    add => left + right,
    subtract => left - right,
    multiply => left * right,
    divide => left / right,
    modulo => left % right,
  };
}
enum EntryPhase { editing, pending, evaluated, error }

EntryPhase distingue quatro momentos. Em editing, estamos montando o operando. Em pending, já existe um operador esperando o próximo número. Em evaluated, há um resultado concluído. Em error, uma nova operação não pode continuar a partir de uma conta inválida. Saber a fase evita que repetir igual reaplique acidentalmente uma operação antiga.

O método público applyCommand é a fronteira de entrada. Ele recebe um comando por vez, como 7, +, AC ou DEL. No caminho dos dígitos, aceita somente um algarismo ou ponto; texto arbitrário e expressões coladas não viram código executável. A interface também converte a vírgula do teclado para ponto. Não existe eval ou execução de texto digitado.

5. Defina as transições antes dos botões

Quando outro operador chega antes do próximo número, ele substitui o operador pendente. Ao confirmar uma etapa, o resultado passa a ser o primeiro operando da etapa seguinte. O trecho atual que registra a operação é:

void _setOperation(Operation operation) {
    if (_phase == EntryPhase.editing && _operation != null) _evaluate();
    if (_phase == EntryPhase.error) return;
    _left = double.parse(_result);
    _operation = operation;
    expression = '$_result ${operation.symbol}';
    _phase = EntryPhase.pending;
  }

Um número depois de igual inicia uma nova conta. Um operador depois de igual continua o resultado. Igual sem segundo operando e igual repetido não fazem uma operação adicional. AC reinicia tudo. DEL remove um dígito durante a edição; depois de um resultado completo, limpa a entrada. O botão ± troca o sinal sem tentar interpretar o sinal de subtração como um dígito.

Precisão: a entrada aceita até 12 dígitos, sem contar sinal e separador. As operações usam double e o resultado confirmado é formatado com 12 algarismos significativos; a conta seguinte usa esse resultado arredondado. Assim, 0.1 + 0.2 aparece como 0.3 e 1 ÷ 3 aparece como 0.333333333333. Valores muito pequenos podem usar notação científica e, por underflow, chegar a zero. O limite de magnitude é um trilhão. Esta é uma calculadora didática, não um motor de cálculo financeiro exato.

6. Faça erros se tornarem estados recuperáveis

Dividir por zero não deve deixar Infinity no visor nem impedir a próxima interação. A verificação acontece antes da operação; módulo por zero segue a mesma regra. Depois, o domínio rejeita resultados não finitos ou além do limite. Veja a implementação atual completa dessa etapa:

void _evaluate() {
    final operation = _operation!;
    final right = double.parse(_result);
    expression = '${_format(_left)} ${operation.symbol} $_result =';
    if (right == 0 &&
        (operation == Operation.divide || operation == Operation.modulo)) {
      _fail('Não é possível dividir por zero.');
      return;
    }
    final value = operation.calculate(_left, right);
    if (!value.isFinite || value.abs() > 1e12) {
      _fail('Resultado fora do limite de 10¹².');
      return;
    }
    _result = _format(value);
    _operation = null;
    _phase = EntryPhase.evaluated;
  }
  void _fail(String message) {
    error = message;
    _operation = null;
    _phase = EntryPhase.error;
  }

A mensagem orienta a recuperação. Um número, AC, DEL ou troca de sinal permite começar novamente; operadores e igual não reutilizam um estado de erro. Essa decisão pertence ao domínio e por isso também é exercitada nos testes. Na interface, tanto o resultado quanto a mensagem são expostos à árvore semântica, em vez de depender apenas da cor.

7. Conecte o estado ao Material atual

O ponto de entrada abaixo é o arquivo main.dart atual. Ele usa material_ui, Material 3 e construtores constantes. Não precisa mudar a orientação da tela dentro do método build:

import 'package:material_ui/material_ui.dart';
import 'calculator.dart';
void main() => runApp(const MyApp());
class MyApp extends StatelessWidget {
  const MyApp({super.key});
  @override
  Widget build(BuildContext context) => MaterialApp(
    title: 'Calculadora',
    debugShowCheckedModeBanner: false,
    theme: ThemeData(
      useMaterial3: true,
      colorScheme: ColorScheme.fromSeed(seedColor: const Color(0xff176b59)),
      scaffoldBackgroundColor: const Color(0xfff4f3ec),
      fontFamily: 'sans-serif',
    ),
    home: const Calculator(),
  );
}

Calculator mantém uma instância de Memory. Ao apertar uma tecla, _apply chama applyCommand dentro de setState; a reconstrução lê result, expression e error. Cada botão envia um comando, sem repetir a aritmética no widget. Os detalhes do teclado estão no fonte completo e validado.

O layout usa uma coluna em telas estreitas, com a calculadora antes das notas, e duas áreas lado a lado no desktop. Em telas baixas, a página rola. O resultado tem alinhamento à direita e algarismos tabulares; os alvos de toque têm pelo menos 48 pixels lógicos. O texto de apoio, o contraste e o espaçamento participam da leitura tanto quanto a paleta de cores.

No teclado físico, Enter calcula, Esc ou Delete limpa, Backspace apaga e F9 troca o sinal. Os operadores +, -, *, / e % também funcionam; vírgula e ponto podem iniciar decimais. Tab e Espaço continuam disponíveis para navegar e ativar os controles. O foco de um botão não deve impedir o Enter de concluir uma conta.

8. Verifique comportamento, não apenas aparência

Os testes do domínio verificam resultados observáveis: operadores suportados, avaliação sequencial, decimais, sinais, limpeza, backspace, divisão/módulo por zero, comandos inválidos, limites e arredondamento. Os testes de widget exercitam toque, teclado, recuperação e layouts com texto ampliado. Estes são os comandos usados nesta revisão:

dart format --output=none --set-exit-if-changed lib test
flutter analyze --fatal-infos
flutter test --coverage
flutter test --platform chrome
flutter build web --release --no-web-resources-cdn

O build Web fica em build/web. Para conferir o resultado de produção localmente, sirva essa pasta por HTTP:

python3 -m http.server 8783 --bind 127.0.0.1 --directory build/web

Abra http://127.0.0.1:8783 no navegador. A hospedagem Web mostra preparação inicial e permite tentar novamente se a inicialização falhar ou demorar. O comando acima serve apenas neste computador; não publica um site.

Nesta revisão foram validados análise estática, 15 testes Flutter, 15 testes Chrome e build Web de produção. A interface foi conferida no navegador em execução real, incluindo viewport móvel. Não foi feito teste em telefone físico nem com leitor de tela. Não há build nativo aprovado nesta revisão; as licenças Android continuam pendentes e os limites das tentativas anteriores estão no log. Acompanhe o workflow fixado no repositório e seu resultado em GitHub Actions.

5 exercícios para praticar

  1. Tipografia com acessibilidade. Escolha uma fonte cuja licença permita uso no aplicativo e declare o asset localmente. Preserve alinhamento e leitura de 12 algarismos. Critério de conclusão: nenhuma sobreposição ou corte a 320 pixels de largura e texto ampliado em 1,8 vez; acrescente um teste de widget para um resultado longo.
  2. Identidade visual e ícone. Crie um ícone próprio e substitua os assets Web, Android e iOS, preservando as dimensões exigidas e o crédito dos recursos utilizados. Critério de conclusão: manifesto Web e catálogos nativos apontam para os novos arquivos; confira o ícone no navegador, sem afirmar validação em plataformas que não executou.
  3. Inicialização clara. Personalize a tela de preparação Web e os recursos de lançamento nativos. Mantenha uma ação para tentar novamente em caso de falha, sem adicionar uma espera artificial. Critério de conclusão: com a rede limitada ou um recurso ausente, a pessoa entende o que ocorreu e consegue repetir a inicialização; registre como verificou cada cenário.
  4. Copiar o resultado. Adicione uma ação explícita para copiar o resultado usando Clipboard, do SDK Flutter, e confirme a ação com texto acessível. Não copie automaticamente e não ofereça um valor de erro como resultado válido. Critério de conclusão: um teste confirma o texto copiado e outro verifica o comportamento durante um erro; preserve o foco do teclado.
  5. Histórico de operações. Guarde no máximo dez etapas concluídas, exibindo operação e resultado em uma área rolável. Decida e documente se AC também limpa o histórico; erros não devem virar resultados válidos. Critério de conclusão: testes cobrem ordem, limite de dez entradas, limpeza e divisão por zero; a tela continua utilizável em viewport estreito e com texto ampliado.
